# Plex covers play on Apple TVs through AirPlay, in a .NET library

A movie or episode opened in the Plex recently-added screen has a **Play on AirPlay** button. HomeyDash's API finds the
Apple TVs on the network, and tells the one someone picks to play an HLS stream of the item. The Apple TV fetches the
stream from the Plex server itself; the display is only the remote. The AirPlay protocol lives in its own library,
`libs/airplay` (`HomeyDash.AirPlay`), which the API uses directly: mDNS discovery, HomeKit PIN pairing, pair-verify, the
encrypted control and event connections and the video playback commands.

## Considered Options

- **A [pyatv](https://pyatv.dev) sidecar** (a small Python service next to HomeyDash). Built first and dropped: pyatv's
  `play_url` is broken on tvOS 26 and later (the Apple TV answers 403 to the old `/play` flow; upstream issues #2774,
  #2821 and #2906, with a fix only in an unmerged rework). Waiting on, or pinning, an unmerged rework in a second
  service, image and language was worse than owning the protocol here.
- **Play in the display's own browser and use Safari's AirPlay picker.** Rejected: it only works on Safari displays, the
  display would stream the video itself, and it is not what was asked for.
- **Send the item to the Plex app on the Apple TV** through the player API [ADR-0009](0009-plex-tiles-through-homeydash.md)
  already uses. Not AirPlay, but it needs no AirPlay at all; still open as an alternative.

## Consequences

- There is nothing else to run or ship. Finding receivers needs multicast DNS, which reaches the network from a container
  only with host networking (Linux); on Docker Desktop (macOS, Windows) run HomeyDash directly on the computer.
  `AirPlay:Enabled=false` switches it off, `AirPlay:Fake=true` runs against made-up Apple TVs.
- Crypto the framework lacks (Ed25519, X25519) comes from BouncyCastle, which is pure managed code. SRP-3072, HKDF,
  the HAP frame encryption, TLV8 and binary property lists are written here, and tested to give the same bytes as pyatv
  and srptools for fixed inputs (`libs/airplay-tests/Vectors`, regenerated by `make_vectors.py`) and against a fake
  Apple TV that runs the receiver's side of pairing and playback over real sockets.
- The playback sequence is the one tvOS 26 and later wants: a command stream (`SETUP` type 130), then `insertPlayQueueItem`
  and friends as `POST /command`, with the playing state read from the event connection. It follows the unmerged pyatv
  rework; Apple does not document it, so a tvOS update can change it again.
- Only receivers with AirPlay's video feature are offered: Apple TVs. HomePods, Sonos speakers and Macs are not (they
  would need audio streaming, which Plex covers do not have).
- The stream URL carries the Plex account's token, because the Apple TV fetches it directly. It goes only from the API to
  the receiver, on the home network ([ADR-0001](0001-trust-the-home-network.md)); screens never see it, and the API's logs
  leave the query out.
- A receiver that wants a PIN is paired once, in Management → Accounts → AirPlay: the Apple TV shows a PIN, and the
  credentials are kept in `airplay-credentials.json` next to the database, in the text form pyatv uses (so a pairing made
  with it still works). The same panel shows whether AirPlay is on and which Apple TVs were found.
- A receiver that cannot play what it is given starts and stops at once, saying nothing. So the API makes the stream
  one an Apple TV plays and checks it first: audio is always transcoded, video is copied only when it is H.264, the
  server is addressed by its IP over http when that answers (a `…plex.direct` https name needs public DNS to give a
  private address, which routers and DNS filters often refuse), and the playlist, a variant and the first segment are
  fetched as the receiver would before anything is sent to it. A failed check comes back as the reason.
  `GET /api/accounts/airplay/stream-check` shows that check for the newest movie or episode, without the token.
- Only movies and episodes play; a season or album has nothing single to stream, and a search can find any item of the
  library, not only the newest (`SearchPlex`; playing looks the item up on the server).
- What plays where is one state in the API (`AirPlayNow`), pushed to every screen as `AirPlayNow`: started on one screen,
  the Plex card on another shows its controls (pause, resume, stop) and a playing badge. The Apple TV doesn't report its
  position, so the API counts it itself (not while paused) and the state ends when the receiver ends the session.
- Audio and subtitle are chosen from the item's tracks in Plex (`PlexTracks`). The stream is one the Plex server makes, so
  a change starts it over from the counted position with the other `audioStreamID` or `subtitleStreamID` (`offset` is
  where it starts); a subtitle is burned into the picture, so the video is then transcoded instead of copied. The position
  can be a few seconds off, and the receiver may pause the picture while the stream restarts.
